# Project notes

- Never use em dashes anywhere in the project (UI text, HTML, docs, comments). Use a bullet (•) instead, or a semicolon in sentences set in the body font (Manuale, Andada Pro's italic), where bullets look out of place. `tests/style.test.ts` enforces this.
- Player-facing text takes curly apostrophes and quotes (’ “ ”), never straight ones: they suit the body font, where a straight ' is a bare tick. Code, CSS and item names (as `items.json` spells them) keep straight ones; a developer's string inside game code (a WebGL program's label) is held to the player rule, since the check can't tell it apart. `tests/style.test.ts` checks what `tests/playerText.ts` finds players reading.
- The display font is Maragsâ Display (`src/assets/fonts/maragsa-display.woff2`). Its license only allows serving it as WOFF/WOFF2 through `@font-face`, so don't add the OTF. Its digits don't fit the UI, so its `@font-face` leaves out 0-9, + and − and they render in Cinzel. The name PoE2.Quest (start page title, header button) keeps Maragsâ digits (`--font-title`). Room codes, the in-game header and avatars use Cinzel (`--font-cinzel`).
- Item tooltips (`ItemDetails.svelte`, in the item window and the codex) use the game's own font, Fontin SmallCaps (`--font-tooltip`; a gem's description in Fontin Italic, `--font-tooltip-italic`). Its license allows `@font-face` embedding only with the notice `/* A font by Jos Buivenga (exljbris) -> www.exljbris.com */` beside the declaration; keep it in `app.css`, and keep the `fontinNotice` plugin in `vite.config.ts` that puts it back into the minified CSS.
- Secondary text (a hint, a status, a caption, an aside) is the game's italic, which sets it apart from primary text: never set it upright to make it read. The body font is Manuale upright with Andada Pro's italic, one family in `app.css` (`--font-body`). The greys stay dim so the gold leads: a note in `--note`, a label or an aside in `--muted`, the dimmest, and nothing under it (the five greys, `--text` down to `--muted`, are named in `app.css`; no hex of its own), never brightened toward `--text` to read better; a line that reads badly gets a better face or size (`docs/design-rules.md`, "Secondary text"). `tests/legible.test.ts` holds the greys to `--muted` and checks the font's faces; the QA desk flags text under it on screen ("Hard to read").
- Phones down to 375px wide are supported (the in-game layout is tuned for that); narrower screens such as 320px aren't a target. In a game a phone never scrolls, on its side or upright: the game fits the screen (`flat` and `upright` in `src/lib/layout.ts`; the QA desk flags a game that scrolls at those sizes, among them a phone's browser with its bars up, 844 x 340 and 375 x 635).
- Arcane or alchemical visuals (rune circles, seals, sigils, ornaments) follow `docs/arcane-style.md`. Before drawing anything in that style, read its sections up to "Engraving techniques" and the reference (the eye: its geometry in `src/lib/plates/eye.ts`, built in a worker, and its component `src/components/ArcaneCircle.svelte`); before animating, "Motion" too. The rest (the script, the other plates, shared pieces) only when the piece uses them.
- Write `cursor: pointer`, `default`, `not-allowed`, `text`, `zoom-in`, `grab` and `grabbing` plainly: the same PostCSS step makes them read the app's own engraved cursors (`src/lib/ownCursor.ts`, drawn from `src/lib/pointerArt.ts`, the shapes other players' pointers are drawn in too), with the system's cursor as the fallback. Middle-button scrolling is the app's own too (`src/lib/autoscroll.ts`).
- The game never holds still for a system that asks for reduced motion, and has no setting for it (the owner's call: no player sees the site without its motion). The battery saver is a touch device's alone, for a phone's battery (`SAVER_OFFERED` in `src/lib/fx/core.ts`, any device with a touch screen): no switch for it anywhere else, nothing switches it there, and one saved there isn't followed (`tests/saver.test.ts`). The still mode is the checks' only (`src/lib/still.ts`: a scripted browser asking for reduced motion, as the sweep and the headless checks do). Write its CSS plainly, `@media (prefers-reduced-motion: reduce)` at the sheet's top level (not inside a rule): a PostCSS step (`stillMark.ts`) turns it into the mode's mark, `html[data-still]`, and stops the build on what it can't say so. In script read `motion.still` or `STILL`, never `matchMedia`. `tests/still.test.ts` enforces this.
- Write `:hover` styles plainly: a PostCSS step in `vite.config.ts` moves every `:hover` selector into `@media (hover: hover)`, so touch screens never get a sticky hover after a tap. JS hover effects check `pointerType === 'mouse'` instead.
- "Ship it" means go live: open a PR into `main` and turn on its auto-merge (`gh pr merge --auto --merge`), no confirming: GitHub merges it once the required checks pass (Redraws takes about 10 minutes; `docs/qa.md`, "Redraws"; the label `skip redraws` passes it in seconds, added only on the owner's word). It has nothing to do with the beta.
- The Workers: `signal/` goes live when it merges (Cloudflare Workers Builds; seeing it live includes Cloudflare's check on the merge commit), `relay/` by hand by the session that changed it, once merged, from a freshly fetched main, with an issue opened beside the PR and closed once it's live. Either keeps working with pages up to two weeks old, and pages with the live Worker; a change needing both lands as one PR. README, "Matchmaking server" and "Relay".
- A change to what's saved (a key in `src/lib/storage.ts`, or what sync carries) keeps reading what older builds saved, with a test loading an older save (as `tests/codex.test.ts` does for the codex's legacy form): no revert undoes saved progress, since sync passes it to every paired device.
- Beta at poe2.quest/beta/ (README, "Beta"); "put this on beta" and "build on beta" are the `beta-deploy` skill. Put a branch on the beta only when the user's latest message asks; never again by yourself after later changes, since parallel sessions share the one beta and overwrite each other's. Use `src/lib/storage.ts` for any localStorage/sessionStorage, so the beta keeps its own.
- A new test or tuning tool is a bench on the QA desk (`src/qa/benches/`, `docs/qa.md`, "Adding a bench"), not a page of its own. Every test or tuning page there still is (a root `.html` beside the game, like `lab.html`) gets a card in the dev hub, `dev.html` (README, "The dev hub"): a link, its path and a line on what it's for, so nobody has to remember its name. Add the page to the beta's build inputs in `vite.config.ts` too; the live build leaves it out. `tests/devHub.test.ts` fails until the card is there. A page the beta doesn't build (like `bot.html`) needs its card left out of the beta, as `devHub` in `vite.config.ts` does for the bot's.
- Headless runs (`npm run sweep`, Playwright scripts, anything that opens browsers) only when really necessary: several sessions run in parallel on this machine and every headless browser slows all of them down. Tests, `npm run check` and reading the code come first; go headless only for what nothing else can settle (whether a layout fits at a size, say), as narrow as it goes (`--only <scene> --sizes <size>`, one size, few pages at once), once, and never as a routine pass after a change. Then follow the `headless-check` skill (hide WebGL, reduced motion) or every step crawls.
- No banding. A soft gradient, glow or shadow spread over a large area steps through so few of 8-bit's levels that each shows as a band, worst in the dark. Draw big ones dithered: on the page's backdrop through the WebGL backdrop (soft shadows `--bs1`/`--bs2`, fills `--bs-fill-*`, text and image glows `use:backdropDropShadow`; see `app.css`), as effects in `src/lib/fx/` (its renderer dithers), and for a see-through dark layer over other content (a scrim, a veil) with `var(--dither)` as its last background layer and `image-rendering: pixelated` (`app.css`). A grain on top only blurs the bands' edges. Check a screenshot with `python3 scripts/find-banding.py shot.png marked.png`.
- Delve is live: bump `DELVE_RULESET` (`src/lib/delve.ts`) only when a change leaves depths not remotely comparable, since a bump sets every player's bests back to nothing (their achievements and codex stay). A smaller change to the curve bumps only `PROTOCOL_VERSION`. Its note in `delve.ts` says where the line is.
- Never give two modules in one folder names that differ only by case once the extension is gone (e.g. `Lab.svelte` and `lab.svelte.ts`): on macOS and Windows the import resolves to the wrong file. `tests/fileNames.test.ts` enforces this.
- Generated, don't hand-edit: `src/data/sceneFiles.json` (`npm run sweep -- --map`), `src/data/items.json` and `itemStats.json` (`npm run fetch-data`), `looks.json` (`npm run looks`), `iconFits.json` (`npm run bake-icons`), `public/icons/lineage-gems.avif` and its 128 px copy (`scripts/cut-gem-icon.py`), `dailyArt.json` (`scripts/daily-art.py`), `dailies.json` (`npm run deal`), `botMotion.json` (`scripts/bot-motion.mjs`), `src/lib/lookalikes.ts` (`scripts/make-lookalikes.mjs`), `sigilEngravings.json` (`scripts/engrave-sigils.py`).
- Delegating: a subagent is the `worker` type (`.claude/agents/worker.md`; Agent `subagent_type: "worker"`, a workflow's `agentType: 'worker'`), which carries only the file and shell tools, unless it needs the browser pane, a skill or an MCP tool. Always set its model and effort by the work, overriding any advice to leave them out: grunt work (greps, renames, style checks, checking a change landed, lookups) Haiku; very easy coding Sonnet, medium; medium coding Opus, medium; big or complex coding Opus, high; the hardest problems (a stutter's root cause, deep performance work) Opus, xhigh; reviews, design reasoning and research judgment Opus. Sessions you start take the same table.
- Designing or redesigning a screen: read `docs/design-rules.md` first.
- Changing how a category card looks or moves (`ChooseCategory.svelte`): read `docs/category-cards.md` first. Chromium draws the faces sharp at twice their size, which a flat transform, a filter on the face, or an image through `var()` (or beside gradients) quietly undoes; `tests/cardFaces.test.ts` checks those.
- A stutter or lag gets found with a trace, never answered by drawing less well: `docs/development.md`, "Finding a stutter", says where to start (the stats' Stutter view, then `scripts/pc/` on the PC, the iPhone below).
- A problem on iOS gets measured on the owner's iPhone, driven from this PC over USB (`docs/iphone.md` from "Every time" to "Measuring on iOS", then the bold leads of "What the iPhone taught us" (`grep '^- \*\*'`), reading only the findings that fit; `scripts/iphone/`): the owner only plugs it in with Chrome open; never ask them to try builds and report how it feels.
- Checking a change: the QA desk (`qa.html`, `docs/qa.md`), a bench for each thing to try out, live. A change that adds or alters something on screen adds or updates its bench, the way it would add tests: a scene (`src/qa/scenes/`) for the game in a state, or a piece (`src/qa/benches/`) for a component on its own, with the states that matter. The PR links them on the beta (`poe2.quest/beta/qa.html?s=<scene key>` or `?b=<piece>`). Keep the desk easy: no new always-visible controls (`docs/qa.md`, "Keeping it easy").
